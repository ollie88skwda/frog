## What Frog is

Frog is a **training lab notebook**, not a workout tracker. Every session is treated as a controlled experiment: you log the work (exercises, sets, reps × weight, RIR) *and* the conditions around it (sleep hours, bodyweight, pre-workout carbs, caffeine, stress, meal timing), and the app surfaces correlations between inputs and outputs — **"Findings"** ("your top sets average heavier on 7h+ sleep"). Findings are transparent statistics (robust trend fitting, median-split heuristics) with honest guardrails: minimum sample sizes, visible confidence, and an explicit "correlation, not causation" caveat. No AI/ML black boxes.

The second moat is **open, code-accessible data**: JSON/CSV export, a personal-access-token read API, an MCP server, and AI-buildable docs (`llms.txt`), so users can point their own tools and AI at their training data. Full product spec: `docs/superpowers/specs/2026-06-20-frog-prd.html`.

Target user: intermediate/advanced lifters who autoregulate and control variables — especially the quantified-self slice. But a minimalist logging only reps × weight still gets a clean, fast tracker.

## The name

The app is **Frog**. The single source of truth for the display name is `APP_NAME` in `packages/core/src/config.ts` — never hardcode the literal in code. Three static assets can't import it, so a rebrand is that one line plus those files by hand: `apps/web/index.html` (`<title>`, the Apple web-app title, and the OG/Twitter metas — `scripts/gen-og-image.ts --check` fails CI until they match), `apps/web/public/manifest.webmanifest` (`name`/`short_name`), and `apps/web/public/sw.js` (the default push-payload `title`).

Technical identifiers agree with the display name as of 2026-07-28 — package scope `@frog/*`, `FROG_*` env vars, the `frog_` PAT prefix, the `__frog` E2E bridge global. See `docs/DECISIONS.md` for what was deliberately *not* renamed (`sbl.pastUsers`, the Vercel project).

## Architecture

Web-first rewrite (the original Expo/React Native app is archived on branch `legacy/expo`, tag `expo-final`). One language: TypeScript. No Rust.

| Path | What | Stack |
|---|---|---|
| `apps/web` | The app — Vite React SPA | React, react-router v7, TanStack Query, Tailwind v4, shadcn/ui (vendored), Convex HTTP transport |
| `packages/core` | Framework-free domain logic, findings engine, Drizzle pg schema, `Repo` interface | Pure TS, zero UI imports |
| `packages/mcp` | MCP server (stdio) — thin client over the PAT API | @modelcontextprotocol/sdk |
| `convex/` | Backend: schema, owner-scoped queries/mutations, file storage, token-API HTTP actions, Clerk auth config | Convex |
| `supabase/migrations/` | **Frozen schema history** (pre-2026-11-01 Postgres) — kept until the prod import has run; also the input to `scripts/convex/pg-replay.ts` (global-seed generation, import round-trip test). No new schema migrations; a seed-only SQL file (owner-null rows, e.g. a machine-catalog batch) may still be added — it reaches Convex only via `convex:seed:generate` → `convex:seed`. | SQL |

**Storage is Convex, online-first** (since 2026-11-01, `docs/DECISIONS.md`). The browser calls Convex queries/mutations over plain HTTP via `convexHttpTransport` (`packages/core/src/repo/convex-http.ts`) — no websocket client; TanStack Query owns caching. **Identity is Clerk** (Google + email, prebuilt UI): every call carries a Clerk token from the `convex` JWT template (`getToken({ template: "convex" })`), validated by `convex/auth.config.ts` (issuer = deployment env `CLERK_JWT_ISSUER_DOMAIN`, applicationID `convex`). Every public function authorizes from `ctx.auth.getUserIdentity()` via `requireUser` (`convex/lib.ts`) and keys ownership off the token `subject`. An account is required; there is no local database on web. **Do not promise offline in UI copy.**

**The Repo seam:** all data access goes through the `Repo` interface in `packages/core/src/repo/`. `ConvexRepo` (`repo/convex.ts`) is the v1 implementation, written against a tiny `ConvexTransport` interface so `packages/core` never imports the `convex` package at runtime. This is deliberate: a future mobile app (Capacitor wrap or native) adds a local-store/offline `SqliteRepo` behind the same interface without touching screens or domain code. Keep the SPA Capacitor-compatible: no SSR, no Node APIs in `apps/web`, browser APIs behind capability guards.

`packages/core` must stay framework-free — no React, no DOM, no backend-client imports outside `repo/`. Domain modules (`units`, `e1rm`, `progression`, `session-reducer`, `ids`) are pure and unit-tested; the findings engine builds on them.

**Freeform-text → structured-data matching — one matcher, `packages/core/src/domain/match-exercise.ts`.** Voice logging and the routine builder's "Paste workout" import (`generator/parse-routine.ts`) both score against it; it's barrel-exported (`matchExerciseName`, `sameExerciseName`, `normalizeExerciseName`, `isConfidentMatch`, `MatchCandidate`, `ExerciseMatch`). `MatchCandidate.aliases` lets a custom exercise's alternate names ("OHP") resolve the same way as its primary name. Each caller sets its own confidence bar via `isConfidentMatch`'s threshold param (voice logging's default, 0.6, stays strict since a misheard word can't be double-checked). This used to be two independently-built matchers with the same exported names and different shapes (`generator/match-exercise.ts` + this file) — before adding a *second* matcher for some new freeform-text feature, remember that's exactly how that happened the first time.

## Constraints (product requirements, not preferences)

- **Mobile-first, always.** Frog is a **mobile web app**. Design and build every screen for a phone / touch viewport *first*; desktop is only a secondary widening of the same layout, never the starting point. Tap targets on the logging path are ≥40 px; never gate an action behind hover-only affordances (a mobile user can't hover). Popups/menus must open fully visible on a phone — never clipped by an `overflow-hidden` ancestor or hidden behind sibling controls.
- **Buttons are never bare text.** Every button and actionable control carries a *visible* background — filled, translucent, or an outline surface — so it reads as pressable at rest, without relying on a hover state. A hover-only background does not count. (`ghost` in `ui/button.tsx` keeps a translucent fill for exactly this reason.)
- **Lightweight & fast.** Audit every dependency before adding it; prefer a few lines over a package. Initial JS budget: **≤220 kB gzipped**, gated in CI by `scripts/check-bundle.ts`. That script carries a *second*, unrelated gate: a `MARKERS` table of dev/test-only strings that must never reach a production chunk — the `__frog` E2E auth-bridge marker (`apps/web/src/lib/test-hooks.ts`), and the click-to-comment overlay's window hook and JSX source stamps (see the Conventions bullet below). Every entry matches the **emitted shape** (`.__frog` as a property access, the stamp as a quoted object key), never a bare substring — the `/changelog` chunk compiles every line of `docs/DECISIONS.md` verbatim and permanently quotes "`__frog`" in prose (2026-08-04). The flip side: **`docs/DECISIONS.md` itself must never write a marker in its emitted shape** (use bracket notation / plain backticks), or it trips the gate on a clean build. Each marker name is written out in exactly two places, the source that emits it and `check-bundle.ts` — **rename it in both or the gate silently passes while protecting nothing.** Prove they still bite by inverting them: a `VITE_E2E=1` build must fail the script, a clean build must pass.
- **Optimistic UI.** Logging a set never waits on the network: client-generated UUIDs (`newId()`), fire-and-forget mutations with retry, UI state already correct. Visual feedback within ~100 ms. **Because those mutations retry (`retry: 3` on the app QueryClient), every write on this path must be idempotent on the client-generated id** — thread the optimistic id into the repo call and upsert on it; a write that mints a fresh id server-side duplicates the row whenever a response is lost after landing. Contract: `Repo.logSet` in `packages/core/src/repo/types.ts`.
- **Lazy-load** non-critical routes (findings/history/settings/library); virtualize long lists only when profiling demands it.
- Measure, don't guess: profile before and after anything that risks bundle size or interaction latency.

## Conventions

- **Routine editor and session are feature-parity by rule (2026-08-08).** Every option the session offers a set or exercise (laterality bilateral/unilateral, warm-up, per-set remove) must exist in the routine editor (`apps/web/src/screens/routine-edit.tsx`) and vice versa — the two screens drifted apart once, and UI feedback batch 8 (notes 10/13) rebuilt the routine editor against the session as the reference: the exercise card's inline buttons became a ⋯ menu, the per-set remove X became a per-set ⋯ menu (laterality + remove), and `routine_sets.laterality` (the per-set prescription) flows into the session through `SeedSet.laterality` → the live spotlight's per-set `lateralityOverride` (`ExerciseBlock` in `session.tsx`, post-2026-08-12 Spotlight redesign; formerly the ActiveRow's per-set draft override). The 2026-08-12 Spotlight-parity pass (`docs/DECISIONS.md`) is the current shared reference: supersets and the drop/failure set types are being removed from the product per session-redesign-r3 decision #8 — the routine editor stopped offering them on 2026-08-12 and the session-side removal ships with the Spotlight branch — so do not re-add them to either screen in the name of parity. A new session-side option ships with its routine-editor counterpart in the same batch, and a new routine-side option must round-trip through `seedFor`/`SeedSet` — the two screens never drift again.
- **`docs/DECISIONS.md` is a merge magnet**: every PR appends a top-level bullet, so any main merge into a PR branch conflicts there (append-vs-append, occasionally plus an in-place SUPERSEDED edit elsewhere). That is the expected shape, not a semantic clash — resolve by keeping **both** entries as top-level bullets (the `/changelog` parser silently drops anything else) newest-added first, and let git auto-merge everything else.
- **Library components first — Radix UI or shadcn — for all UI components and charts.** Never hand-roll a component or graph when a maintained library component exists (Radix primitives via the vendored shadcn/ui in `apps/web/src/components/ui/`, direct `@radix-ui/*`, shadcn charts, Phosphor icons via `@phosphor-icons/react`). Custom code only when no library component fits — and say why (the PR body; a lasting call goes in `docs/DECISIONS.md`). The one surviving hand-drawn chart code is the **body heat maps** (`components/charts/body-paths.ts` + `human-body-heatmap.tsx`) — no maintained library component has a heatmap figure, so they stay as a deliberate zero-dep/bundle-budget call (the in-house bar/line/sparkline kit was deleted 2026-08-08; see `docs/DECISIONS.md`). Not a license for new hand-rolled components.
- **Shared row/icon-button chrome (`apps/web/src/components/ui/`), app-wide since the 2026-08-13 row-layout sweep.** `IconButton` (button) / `IconLink` (nav — pass `as={Link}` for react-router) are the one square icon-control treatment: 40px touch / 32px desktop, borderless `bg-surface-2` tone fill with `rounded-sm`, `active`/`danger` variants — never a bare icon `<button>`/`<Link>` with only `hover:text-*` and no resting background (AGENTS.md's no-bare-buttons rule). `BackButton` (`ui/back-button.tsx`) is the header back-arrow built on those two, `to`-for-Link or `onClick`-for-`navigate(-1)`. `Toolbar` groups a header's right-side icon buttons with uniform spacing. `Row`/`rowClass` (`ui/row.tsx`) is the fixed-height list-row template (44px touch / 32px desktop, `px-4`, optional hover) that dense data lists (history, findings, records, tokens, …) render through instead of a bespoke flex row — pass `interactive={false}` for a non-clickable row, or use `rowClass()` directly when the row itself must be a `<Link>`/`<button>`. **Exempt by established convention, don't "fix" these**: floating dropdown/popover menu items (session's `BlockMenu`, routines' folder/routine menus) stay hover-only with no resting background — the popup itself is the affordance; collapsible section-header disclosure toggles (library's muscle-group header, exercise-detail's Set records toggle) are the same pattern. `session.tsx`/`routine-edit.tsx` and components they exclusively import (`conditions.tsx`, `lesson.tsx`, `machines.tsx`, `exercise-editor.tsx`) were out of scope for the sweep — check a component's importers before assuming it's fair game.
- **IDs:** uuid v4, generated client-side via `newId()` from `@frog/core`.
- **Timestamps:** `created_at` / `updated_at` / `deleted_at` are bigint millisecond epochs, app-managed (`Date.now()`).
- **Soft delete only:** set `deleted_at`; never hard-delete; IDs are never reused.
- **Weight:** stored canonically in **kg** (`weight_kg`); kg/lb is a display setting (`domain/units.ts`).
- **Ownership:** every row has `ownerId` (`owner_id` in the Postgres-shaped types/export) = the token `subject` (a Clerk user id; `e2e-…` for minted test identities); global seed rows have `ownerId null`. There is no RLS: **the Convex functions are the boundary**, and they match the old RLS semantics exactly (`convex/lib.ts`, `convex/tables.ts`): an update/delete matching nothing the caller owns is a **silent no-op** (resolves, zero rows changed — so `mutate()`'s fire-and-forget callers see nothing wrong), an insert referencing a parent the caller can't see throws, a client `ownerId` is overwritten with the caller, and an insert reusing someone else's id throws. Global rows are written only by `internal` functions in `convex/admin.ts` (seed/import, admin key) and by `exercises:publish`. **Community-shared exercise rows** (`docs/DECISIONS.md` 2026-08-08) are `ownerId null` + `isCustom true` + `createdBy` = the publisher — created **only** by `exercises:publish` (the port of the `publish_exercise` RPC: validation, case-insensitive name backstop and rate limit in one place; the RPC's `revoke execute` off-switch did not port, so stopping publishing server-side now takes a code deploy); never let a generic write path admit `ownerId null`. `COMMUNITY_SHARING` (`packages/core/src/config.ts`) is the app-side switch; shared rows are immutable afterward, so editing them forks a private copy (`share: false`). Any new write to a possibly-shared/seed row must go through the fork gate (`isCustom && ownerId !== null` → patch in place, else fork) — see `screens/routine-edit.tsx`'s `patchExerciseField` and the session `BlockMenu`'s `forkExercise` (`docs/DECISIONS.md` 2026-08-12). **Private files:** bytes leave only through the Clerk-authenticated HTTP action `GET <site>/files/<storageId>` (`convex/http.ts`), which `ConvexRepo` turns into a local object URL; never hand out `ctx.storage.getUrl` links, which carry no auth and never expire. `files:claim` enforces the 50 MB limit. No admin/deploy keys in app code. The test JWT issuer in `convex/auth.config.ts` exists only when the deployment env `TEST_JWKS` is set — **never set it on dev-cloud or prod**.
- **Schema changes:** `convex/schema.ts` is the live schema; `packages/core/src/db/schema.ts` (Drizzle types, no longer emits DDL) stays the source of the app's row types and the snake_case column names used by the export, the token API and the importer (`db/columns.ts`). Add a field to both. `supabase/migrations/` is frozen. Global seed rows come from `scripts/convex/global-seed.json` (generated by `bun run convex:seed:generate`; upserted by `bun run convex:seed`).
- Tables: `exercises`, `metrics`, `sessions`, `session_exercises`, `set_logs` (+ `api_tokens`). Custom metric/condition values live in jsonb (`condition_values`, `metric_values`).
- **`machine_catalog` vs `machines`**: `machine_catalog` (added 2026-08-07, `docs/DECISIONS.md`) is a global, seedable-owner reference catalog of real gym-machine models (brand/model/specs) — the DB analogue of the static `packages/core/src/data/machine-catalog.ts` array, seeded from it (Tier 1 brands). `machines` is unrelated in shape: a user's *owned equipment*, owner-required, no seed rows (`docs/schema.md`). The app reads `machine_catalog` only through `Repo.searchMachineCatalog` / `Repo.listMachineCategories` (Convex queries `exercises:searchCatalog`/`exercises:catalogCategories`, ports of the old `search_machine_catalog` SQL RPCs — server-side case-insensitive substring match over brand/model/category/aliases, no fuzzy matcher, at 867 rows) and never imports the static TS array (the picker dropped it, so it ships in no bundle); a machine picked from the catalog stores the catalog row's **uuid** in `machines.catalog_key` (text — the planned real FK swap is still outstanding). **Acquiring new rows**: the phase-2 pipeline (`scripts/machine-catalog/`, `docs/machine-catalog-pipeline.md`) crawls brand storefronts → mock/live extraction → QA. Two rules for whoever adds the next brand: only `life-fitness` and `hammer-strength` are `verified: true` (`brands.ts` — flip it only after checking that domain's robots.txt/ToS yourself), and a new batch must dedupe against the phase-1 seed before migrating — `qa.ts` writes `staging/qa/<brand>-review.json` (batch minus seed overlaps via `findSeedOverlaps` — same machine under the seed's "Plate Loaded"-prefix/word-order naming counts as a dupe) and `generate-migration.ts` prefers that file. Its seed SQL goes into `supabase/migrations/` and then through `bun run convex:seed:generate` + `bun run convex:seed` to reach Convex.
- **A unilateral set is TWO `set_logs` rows sharing one `set_no`**, distinguished by `side` (`'left' | 'right' | null`; null = the whole set — bilateral, alternating, every pre-existing row). Never count physical sets by counting rows — use `countSets()` (`domain/volume.ts`), which every set-count surface (session header, finish sheet, stats, share cards) is built on. The same applies to *projecting* sets outward (routine write-back, save-as-routine, copy-workout seeds, committed-row rendering): group with `groupSetsBySetNo()` and emit one output per group with the left row as the template — one output per row shifts or doubles every set after a pair. And **every surface that renders a *prior* set** (session PREVIOUS cell, library "Last:" line, any history preview) must format it through `formatPrevious()` (`domain/previous.ts`), which owns the uneven-pair convention (`40 kg × 8 / 35 kg × 8`) — reading a `GhostSet`'s own `weightKg`/`reps` inline silently drops the ᴿ side. See `docs/DECISIONS.md` 2026-08-01.
- **Muscle targets carry an explicit role.** `exercises.muscle_targets` is `{muscle, tier, role?}[]`; `role` is `"primary" | "secondary"` and an exercise can declare two primaries (e.g. Romanian deadlift: hamstrings + glutes). Absent `role` is a back-compat case, not an error — it means index 0 is primary and everything after is secondary. Always resolve it through `roleAt()`/`primaryMuscles()`/`secondaryMuscles()` (`domain/anatomy.ts`); don't re-derive the rule inline. Library grouping and generator matching still key off the first target regardless of `role` (`primaryMuscleKey`) — role changes muscle-credit and display, not which shelf an exercise lives on.
- **"What's next" is one rule.** Whatever routine the app offers next — Home's hero card, the Trainer's next-workout card — comes from `suggestRoutineId` in `packages/core/src/domain/plan.ts` (longest since *completed*, scoped to the active program's folder). Call it; never add a second, subtly different definition. Two screens disagreeing about what today is is a bug, and this repo has already paid for parallel implementations once (see the matcher note above).
- **Ambient browser-API types:** non-standard vendor APIs not in TS's DOM lib (e.g. the Web Speech API) get a minimal ambient `.d.ts` under `apps/web/src/types/` rather than an `any` cast — see `speech-recognition.d.ts`.
- **Per-user module state:** module stores in `apps/web/src/lib/` that hold *user* data (not device prefs) must register their own reset via `registerUserScopedReset` in `lib/user-scoped-state.ts` — `queryClient.clear()` on sign-out / user change doesn't reach module state, so the next account on the device would inherit it. Registration lives in the store, not in `auth.tsx`, which keeps lazy-route-only stores out of the eager bundle.
- **E2E "renders below the fold" tests need a partial scroll, not max scroll.** Every screen wrapper reserves `pb-20`/`md:pb-6` on top of `app-shell.tsx`'s own `<main>` bottom padding (mobile tab-bar clearance) — scrolling a long list to its true `scrollHeight - clientHeight` still leaves ~170px of reserved space below the last item in the built (`vite preview`) app that a dev-server (`vite dev`) session doesn't show the same way. To reproduce a genuinely below-the-fold element, scroll to a few dozen–100px short of max instead (see `e2e/routines.spec.ts`'s popup-flip test) rather than assuming max scroll = flush against the viewport edge.
- **Convex caps the documents one function reads**, so whole-table reads (exercise library, history graph for findings/records, export) are cursor-paged by `data:page` (`convex/data.ts`) and stitched in `ConvexRepo.pageAll` — never `.collect()` an unbounded user table in one function. Order deterministically (a natural column with an `id` tiebreak — ids are random uuid v4). The token API (`convex/tokenApi.ts`) pages the same way server-side; keep the two in step.
- **Week start is hardcoded Sunday** — `FIRST_WEEKDAY` in `packages/core/src/config.ts` (barrel-exported), not a user preference; there is no settings picker (see `docs/DECISIONS.md` 2026-07-30). `weekStart`/`computeStreak` and the stats/report `firstWeekday` options still take it as a parameter (they're generic pure functions), every call site just passes the constant.
- **`biome.json`'s `files.includes` is an allowlist, not a default-scan** — a new top-level source directory (e.g. `e2e/`) is silently unformatted and unlinted by `bun run lint` until it's added to that list. When adding a new top-level dir with `.ts`/`.tsx` source, add it here too.
- **E2E hygiene: every run cleans up after itself, and stale runs get swept too.** E2E and integration identities are JWTs minted by `scripts/convex-test-auth.ts` (sub `e2e-<ms>`), accepted only by a backend with `TEST_JWKS` set (`scripts/convex-test-env.ts` sets it and refuses non-local targets). `COMMUNITY_SHARING=true` means most spec-created exercises land as global rows, so without cleanup the shared local backend's library grows across rounds. `scripts/e2e-cleanup.ts`: `purgeE2eUser(admin, sub)` hard-deletes one test identity's owned + published rows via `admin:purgeTestUser` (refuses any sub not matching `^e2e-[a-z0-9-]+$` — test-infra teardown, not the app's soft-delete convention); `purgeStaleE2eUsers(admin, olderThanMs)` sweeps `e2e-*` owners older than the threshold (default 2h, age-gated because two lanes can share one local backend). `run-e2e.ts` purges its own user after the suite (pass or fail) and sweeps stale ones first. `bun scripts/e2e-cleanup.ts [maxAgeMinutes]` runs the sweep standalone (local hosts only).
- **A raw exception reaches a user only through a transport failure, and one function translates it (2026-08-25).** `convexHttpTransport` rethrows a fetch that never reached the backend as `"<ErrorName>: message"` (`TypeError: Failed to fetch` / `Load failed`), so any screen printing `e.message` would show the user the word "TypeError"; server-thrown `ConvexError`s arrive as `ConvexCallError` with the framing stripped (`cleanConvexMessage`). `userFacingRepoError` (`apps/web/src/lib/repo-error.ts`) is the one translator; route a new raw-message render through it instead of writing a second matcher. `lib/start-session.ts`, `settings.tsx` and `components/import-card.tsx` all route through it; no raw-message render remains. See `docs/DECISIONS.md` 2026-08-25.
- **New routes use `lazyRoute`, and the app has exactly one error boundary (2026-08-25).** A hashed chunk from a superseded deploy is a real 404 (`vercel.json` keeps `/assets/` out of the SPA rewrite), so a tab open across a release used to blank the whole app. `lazyRoute` (`apps/web/src/app.tsx`) retries once then reloads once per tab; `AppErrorBoundary` (`apps/web/src/components/error-boundary.tsx`) catches the rest. Never add a route on bare `lazy()`. The two dev-only lazies stay bare so their dead-branch shape still folds away for `scripts/check-bundle.ts`, and the boundary hand-rolls its button on purpose (importing `ui/button.tsx` costs +3.2 kB gz eager) — both are documented exceptions, not oversights.
- **Shared UI kit additions (2026-11-04 audit pass):** `ui/query-state.tsx` (`QueryState`: loading → error+Retry → empty; use it for every query-backed screen), `ui/confirm-dialog.tsx` (never `window.confirm`), `ui/dropdown-menu.tsx` (Radix; new popup menus use it, not a hand-rolled backdrop), `ui/chip.tsx` (`ChipGroup`/`ToggleChip`), `ui/input.tsx` `Textarea`, `ui/checkbox.tsx`. `Button`/`Input`/`Select` are 40px on touch and 32px at `md:`; `IconButton`/`Button size="icon"` fall back to `title` as `aria-label`; Phosphor icons are `aria-hidden` by default (`IconContext` in `main.tsx`). File pickers use `className="sr-only"` (never `hidden`) so keyboard users can focus them. Per-page findings and what was left undone: `docs/brand/audit/SUMMARY.md`, `docs/brand/redesign-log.md`. Real-Clerk lane (not CI): `e2e/clerk-real.spec.ts` via `e2e/playwright.clerk.config.ts` against a non-E2E build; Clerk test emails `name+clerk_test@example.com`, code 424242.
- **A failed query must never render as an empty one.** `library.tsx`'s `isError` branch and `session.tsx`'s `blocks === null` gate both distinguish "still loading" from "the request failed" and show a plain-language error + retry (`text-neg` + the existing `useVoice()` register, not a new toast system); `logSet` surfaces a failed write the same way once its retries (`app.tsx`) are exhausted (and any local edit/delete of a not-yet-persisted set must reconcile its queued retry payload — see `dropQueuedSets`), and the in-session `ExercisePicker` branches error-before-empty too. See `docs/DECISIONS.md` 2026-08-06 (second entry) for the outage this guards against before changing any of them.
- **Click-to-comment is dev-only and generic by construction — never wire a component for it.** The bare `A` key (or the floating button, for touch) turns any screen into a point-and-comment surface that copies markdown for an agent; full shape in `docs/annotate.md`. Identity is resolved at the DOM level from the event target plus a build-time JSX source stamp (`apps/web/plugins/annotate-source.ts` → `apps/web/src/dev/annotate/`), so **a screen written next year is annotatable the moment it renders, with zero new wiring** — if a change would make someone add a prop, marker or registry entry to a feature component, it's the wrong change. React 19 removed the fiber `_debugSource` field, which is why the stamp exists at all. It never ships: the mount in `app.tsx` is a dead branch in production (same shape as `ThemePanel`) and `check-bundle.ts` gates its markers.

## Commands

```sh
bun install            # workspace install
bun run test           # vitest across packages + apps/web (framework-free logic only)
bun run typecheck      # tsc across packages + convex/
bun run lint           # biome
bun run dev            # vite dev server (apps/web) — needs VITE_CONVEX_URL
bun run test:integration  # ConvexRepo against a local backend (pushes functions, sets TEST_JWKS, seeds)
bun run test:import    # Supabase→Convex import round-trip (PGlite source → local backend)
bun run e2e            # Playwright against vite preview + local Convex
bun run convex:seed    # upsert global seed rows into the target deployment
bun run import:supabase -- --dry-run   # one-off prod data move; see scripts/import-from-supabase.ts
```

A local backend is the default for all dev and tests: run `CONVEX_AGENT_MODE=anonymous bunx convex dev` (or `bunx convex dev --local`) **in its own terminal** — it is long-lived — then, once per new backend, `bunx convex env set CLERK_JWT_ISSUER_DOMAIN https://top-parakeet-48.clerk.accounts.dev` (function pushes fail until it's set), and point the app/scripts at `http://127.0.0.1:3210` (HTTP actions/token API on `:3211`). Scripts that need admin access read `CONVEX_SELF_HOSTED_URL` + `CONVEX_SELF_HOSTED_ADMIN_KEY` (or `CONVEX_URL` + `CONVEX_ADMIN_KEY`/`CONVEX_DEPLOY_KEY`) from env — pass them with `bun --env-file=<file>`, never commit them. The cloud prod deployment exists only for production; CI uses its own throwaway local backend (`scripts/ci/start-convex-backend.sh`).

## Data-acquisition pipelines (`scripts/<name>/`)

A bulk external-data pipeline (crawl → cheap-model extraction → normalize → QA → migration generator) is its own top-level `scripts/<name>/` module, gitignored `staging/` output, own `paths.ts` (root overridable via an env var so a committed reference example can be reproduced without touching the real staging dir), and CLI scripts that run their `main()` unconditionally at module bottom (matching `import-free-exercise-db.ts`) — pure logic that a later stage or a test needs to import lives in a sibling `*-lib.ts`, never in the CLI file itself, so importing it doesn't re-run that stage's CLI. See `scripts/machine-catalog/` (`docs/machine-catalog-pipeline.md`) for the reference shape: brand/domain ToS checklist, env-configurable cheap-model extraction (never a frontier model for bulk structured extraction — bounded JSON-schema extraction is exactly what a fast/cheap model tier is for) with a deterministic dry-run/mock mode when no API key is configured, and a migration generator matching the `owner_id null` / deterministic-uuid / `on conflict do nothing` seed-migration pattern (`supabase/migrations/20260715055811_seed_free_exercise_db.sql`) without ever writing into `supabase/migrations/` itself.

## Design language

**Frog** runs the Because green (Fern) system — spec in `docs/brand/README.md` + `docs/brand/because-reference/` (old identity archived in `docs/brand/archive/`, `docs/DECISIONS.md` 2026-11-03). `apps/web/src/styles/theme.css` is the single token source (`data-theme="green"` + `data-mode="day|night"`, Device/Day/Night); `@radix-ui/themes` is removed (so there is no Radix radius setting at all); the unstyled Radix primitives (`@radix-ui/react-dialog`/`-select`/`-switch`) and the vendored shadcn components are styled only through the Tailwind utilities `theme.css`'s `@theme inline` block aliases onto the Because `--color-*`/`--r-*` roles (`bg-surface`, `text-soft`, `rounded-md`, …), and shadcn's `--chart-1..5` map onto the Fern ramp per mode. Geologica only, Phosphor icons only (never lucide), corners on 4/8/12/16/24, **no borders or lines except the 1px text-field line**. **The split rule:** the closer to the data the more serious — logging hot path, charts, findings statistics are sacred and never goofy; the frog voice lives only at the edges (empty states, loading, toasts, errors, PR banners, 404, settings corners). Copy in playground zones routes through the language registers (`apps/web/src/lib/voice.ts`: Human / Frog / Ultrafrog — a render-time text transform that never changes what is reported). Keyboard-first: ⌘K command palette (bare single-key shortcuts were removed 2026-08-07; the dev-only annotate overlay's bare `A` is the sole exception). All numeric data uses tabular numerals (`.num`) and is never inside a joke. Micro-interactions are 100–150 ms CSS transitions; nothing animates on the data path.

**shadcn/ui is CLI-initialized** (`apps/web/components.json`, radix-nova preset, 2026-08-08) — graphs and non-Radix components come from it (`npx shadcn@latest add <name>`), never hand-rolled. Its CSS token names (`--background`, `--card`, `--muted-foreground`, `--chart-1..5`, …) are **not defined** — shadcn components here use the Tailwind utility aliases in `theme.css`'s `@theme inline` block (plus `--chart-1..5` → the Fern ramp) — do not re-run `shadcn init` (it overwrites `--accent`/`--border`/`--ring`/the font with a neutral palette) and do not add components without checking the bridge. Stats-screen graphs are shadcn charts (recharts 3.8, lazy stats chunk ~113 kB gz); recharts gotchas: category axes key off the data value (sparse labels must be a `tickFormatter` over a unique key) and zero-height bars are skipped. The stats body heat maps are the `react-body-highlighter` library figure wrapped by `components/charts/human-body-heatmap.tsx` (region roll-up still via `body-paths.ts`); Home's teaser and the share cards keep the frog figure.

**Brand mark.** `apps/web/public/icon.svg` and every PNG in `apps/web/public/` are **generated output**, never a hand source: `bun scripts/gen-pwa-icons.ts` builds them from `docs/brand/assets/frog-mark.svg`, itself generated by `bun scripts/vectorize-frog-mark.ts` (needs the `potrace` CLI) from the reference art `docs/brand/assets/frog-logo-reference.jpg`. Never hand-edit `icon.svg` or a PNG; if the reference art changes, re-run both scripts in order. `icon.svg` carries a `@media (max-width: 48px)` rule hiding its two nostril paths (tagged `class="fine-detail"`, found by measuring path bounding-box diagonals, not hand-picked) since they go to mush at favicon sizes; `frog-mark.tsx` (20–32px) has no such treatment — verify small-size changes at 16/32/48px. The mark's geometry is **hand-copied in four places**, all in the brand spec — the app-tile sample, the 16px sample, the standalone in-app-mark sample, and the icon-row copy — and `bun scripts/check-mark-drift.ts` (wired into CI) asserts all four still match their canonical source (`icon.svg` for the tile/16px pair, `apps/web/src/components/frog-mark.tsx` for the in-app-mark pair) and that the two canonical sources agree with each other; re-run it after touching either. What it can't check is `frog-mark.tsx`'s theme recolor, so also eyeball the sidebar mark at 20–32px in both themes. **Needing the mark as a raster (canvas, `<img>`) is not license for another hand-copy**: go through `apps/web/src/lib/share/mark.tsx` (`loadFrogMarkImage`/`drawFrogMark`), which rasterizes the live `FrogMark` component and scales the landscape mark to fit square slots — a bare `drawImage(mark, x, y, size, size)` stretches it, and `react-dom/server`'s `renderToStaticMarkup` adds ~61 kB gz to that lazy chunk versus the `createRoot`+`flushSync` route it uses. Pipeline mechanics, the potrace layering and recolor rationale, and the tile/maskable framing math live in the brand spec's "The mark" section and `docs/DECISIONS.md` 2026-08-06 + 2026-08-07 (the re-trace, which supersedes 2026-08-06's trace/fill/recolor numbers).

**Share cards.** Six typed card kinds (`packages/core/src/share/types.ts`), one canvas layout engine, five frames (Story/Post/Square/Landscape/OG), four grounds (Dark/Light/Photo/Green) — see `docs/share-cards.md` for the full shape (card kinds, frames, grounds, hero-selection rules, typography, footer/OG handling, surfaces, test IDs). Card data assembly is pure and lives in `packages/core/src/share/builders.ts` (unit-tested, no React/DOM); canvas painting lives in `apps/web/src/lib/share/` (`paint.ts`/`frames.ts`/`grounds.ts`/`graphics.ts`); the mobile UI is `components/share-sheet.tsx`. The body heat-map path geometry is the one copy in `components/charts/body-paths.ts` — both the interactive SVG and the canvas painter draw from it; don't add a third copy. The static OG image (`apps/web/public/og.png`) is generated by `scripts/gen-og-image.ts`, which drives the real painter through a throwaway Vite dev server + `apps/web/og-harness.html`/`src/og-harness.tsx` (not part of the shipped app) since it needs the real `FrogMark` component, not raw SVG like `gen-pwa-icons.ts`; re-run it after any painter/brand change, and run it with `--check` (no browser) to verify the OG meta in `index.html` hasn't drifted from `APP_NAME`.
