# DECISIONS.md — SBL decision log

Terse, dated log of product/design/architecture decisions. **Rule: when a new decision overrides an old one, edit the old entry in place — mark it `SUPERSEDED → [see entry]` — so this file never contradicts itself.** Add an entry in the same commit as the change it describes.

## Product

- **2026-06-20** — SBL is a training lab notebook: log work + conditions, surface correlations ("Findings") with transparent stats, no AI/ML black boxes. Second moat: open data (export, PAT API, MCP). PRD: `docs/superpowers/specs/2026-06-20-sbl-prd.html`.
- **2026-06-20** — "SBL" is a placeholder name; single source `APP_NAME` in `packages/core/src/config.ts`.
- **2026-07-14** — **Navigation is Heavy-style: 3 tabs — Home / Training / Profile** (was 5: ~~Train / Library / History / Findings / Settings~~ SUPERSEDED). **Home** (`/`, index) is the lightweight dashboard: quick-start CTA, Findings teaser, Library entry, and a labeled placeholder for the future feed + graphs. **Training** (`/train`) is the full workout hub (start / resume the live session; routines later). **Profile** (`/profile`) holds the public-profile preview stub, recent History (+ link to full `/history`), and Settings (link to `/settings`). `/library`, `/history`, `/findings`, `/settings` remain routes, now reached from Home/Profile rather than top-level tabs. Start-session flow extracted to `useStartSession` (`apps/web/src/lib/start-session.ts`), shared by Home + Training. **Social feed + progress graphs are deferred** — placeholders only, not faked.
- **2026-07-12** — v1 web is online-first (Supabase-direct, account required). Offline deferred to mobile phase behind the `Repo` seam. Never promise offline in UI copy.
- **2026-07-12** — Exercise library organized by **muscle group (primary)** with joint action shown as a label per exercise. ~~Joint-action-primary~~ SUPERSEDED same day: joint actions shift target muscle by ROM (elbow flexion 20–90° biases biceps, >90° biases brachialis/brachioradialis) and grip (pronated/neutral biases brachialis) — too nuanced for top-level grouping.
- **2026-07-12** — **Tier ratings (S/A/B/C)**: per-exercise `muscleTargets` `{muscle, tier}` drives grouping/sorting; core `ACTION_RATINGS` (muscle × joint action → tier + nuance note + citations) powers education and "best exercise for a muscle". Tiers are evidence-informed judgment calls compiled from EMG/MRI/hypertrophy literature; thin evidence is flagged in notes.
- **2026-07-12** — **Machines are separate entities** (own library), not exercise fields: name, brand, catalog link, ordered numbered settings (`[{label, value}]`), notes, photo. In-session setup strip under the exercise header; edits persist to the machine row → "same setup every time, remembered forever".
- **2026-07-12** — **Machine catalog** is a static, lazy-loaded TS module (`packages/core/src/data/machine-catalog.ts`) of real commercial models (Matrix, Hammer Strength, Life Fitness, Technogym, …), scoped to major brands' strength lines — not a DB table, not "every machine ever". Catalog imagery = category line-art icons.
- **2026-07-12** — **Machine photos are user-taken only** (camera upload → private Supabase Storage bucket, owner-scoped). Third-party/manufacturer photos are copyrighted — "publicly visible" ≠ public property — and stay out.
- **2026-07-12** — **Lessons**: in-app micro-education (InfoTip → Dialog). Ultra-concise (couple of lines), optional tiny visual, optional `citations` (PMID/DOI). Seen-state in localStorage. First lesson: RIR (placeholder copy until Ollie supplies final).
- **2026-07-12** — **FUTURE (not built): PubMed science coaching** — rule-based (not necessarily AI) nudges citing studies when a plan choice contradicts evidence. Seams shipped now: `citations` on lessons and on `ACTION_RATINGS`.
- **2026-07-13** — **Exercise reference diagrams** (seed exercises only): `exercises.image_url` + `image_attribution`, hotlinked from Wikimedia Commons, no storage/upload. All diagrams are from the **Everkinetic set (CC BY-SA 3.0)** specifically so every diagram shares one consistent line-art style (same figure, same line weight) — deliberately not a mix of styles/sources. 19 of 20 seed exercises matched; **Face Pull** has no Everkinetic diagram and ships without an image. Custom (user-created) exercises get no image in v1 — out of scope, matches the existing seed-vs-custom asymmetry. Shown as a small `ExerciseThumb` (`apps/web/src/components/anatomy-ui.tsx`) in the library list, session exercise picker, and in-session exercise header. Store the Wikimedia **thumbnail** URL (~250px, `/thumb/.../250px-*.png`), never the full-res original (some originals are 250–400KB — wasteful for a UI thumbnail); for SVG-sourced diagrams, store the **rendered PNG thumb URL**, not the raw `.svg` — Wikimedia serves raw SVGs as `text/plain`, which silently fails to render via `<img src>`.
- **2026-07-13** — **Library exercise ribbon redesign**: bigger card per exercise (64px diagram, up from 24px) with explicit visual hierarchy — name (semibold) > per-joint-action tier ratings (color-coded S/A/B/C badges, computed) > machine/last-set metadata (faint, smallest). **Per-exercise joint-action tiers**: new `ratingsForExercise()` (`packages/core/src/domain/anatomy.ts`) looks up each of the exercise's own joint actions against `ACTION_RATINGS` restricted to the exercise's own target muscles (e.g. Front Squat × knee-extension → S via quads, × hip-extension → S via glutes) — reuses the existing evidence table, no new data. **Favorites**: `exercise_favorites` table (owner_id, exercise_id, favorite bool; upsert pattern mirroring `tracked_conditions`) since favoriting must work on shared seed rows — can't be a column on the shared `exercises` row. Plain star icon toggle, not a 3-dot menu: with only one action today, a dropdown-menu primitive isn't worth adding (no `@radix-ui/react-dropdown-menu` in the repo, bundle budget). **"Last set"**: reuses the existing `lastSetsForExercise` ghost-prefill lookup (no new query) via a new `useLastSets` hook. **"Machines used"**: shows the exercise's single currently-attached machine (`exercises.machine_id`) — there is no historical multi-machine log in the data model (session_exercises doesn't record machine), so this is the remembered current setup, not a history. Session logging screens (exercise picker, block header) keep the small 24px thumbnail — the ribbon redesign is Library-only, to protect the dense/fast keyboard-first logging path.

## Design

- **2026-07-12** — Linear-style techie-modern UI (graph-paper/blueprint identity retired; Expo app archived on `legacy/expo`). Dense 13px, keyboard-first, ⌘K, tabular numerals, 100–150ms transitions, nothing animates on the data path.
- **2026-07-12** — **Blue monochrome, base `#034078`** (user-picked hex). ~~Red monochrome accent~~ SUPERSEDED. Every non-semantic color = `color-mix(in oklab, #034078 N%, black|white)` percentage step; only the hex is locked — step percentages tune against measured contrast. Exceptions: `--pos/--neg/--warn` keep green/red/yellow for findings direction + destructive affordances (small text/icons only, never fills); shadows/overlays stay neutral black/white alpha (they read as light, not color).
- **2026-07-12** — **0px border radius everywhere** (square/brutalist): all `--radius-*` tokens 0, no `rounded-full` pills/dots (squares instead). `status-ring` SVG circle stays (glyph, not radius).
- **2026-07-12** — **8px grid, HARD RULE**: all spacing and box sizes are multiples of 8px (4px sub-steps allowed on mobile/micro-spacing); layouts align to a 12-column rhythm. Type scale (13px base) is exempt — the rule governs boxes/spacing, not glyphs. Do not break this in new UI.
- **2026-07-12** — Mobile-first mandate: every screen designed at 390×844 first; bottom tab bar on mobile (`pb-20` compensation), desktop sidebar.
- **2026-07-13** — **Per-set RPE + rest time + effort-aware e1RM calculator.** `set_logs` gains `rpe real` (1–10, halves allowed; RIR ≈ 10 − RPE) and `rest_sec integer` (seconds rested before the set). Rest is captured automatically on commit from the existing rest-timer baseline (time since the previous set committed this session; null for the first set) — the user never types it. Average rest is surfaced live in the session stats line and per-exercise in history detail. The logging-path optional-field affordance changed from a single `+RIR` toggle to a `⋯` **"add field" menu** (RIR / RPE / Note / each enabled custom metric) so effort/notes/metrics are all opt-in per set and nothing clutters the row until added. The **"calculator"** is `e1rmFromEffort` in `packages/core/src/domain/e1rm.ts`: plain Epley assumes a set taken to failure, so when RIR (or RPE) is known it projects to failure (`reps + RIR`) before applying Epley — a proximity-to-failure correction. Shown as an `e1RM ≈` readout atop the committed-set menu. New columns flow through the repo, CSV export (open-data moat), and are covered by `e1rm.test.ts`. Effort-aware e1RM is **not** yet wired into findings/progression (still raw Epley top-set) — deferred to avoid changing the trend baseline mid-stream.
- **2026-07-13** — **Exercise quality shown as name brightness, not letters.** The exercise name's text color encodes its tier for the current muscle group (`tierNameClass` in `apps/web/src/components/anatomy-ui.tsx`): brighter blue = better (S→`text-ink` … C→`text-faint`); a `TierLegend` key sits atop the Library list. The S/A/B/C `TierBadge` glyph is retained only in editor/ranking UI (custom-exercise muscle editor, "Best for muscle" dialog), not on the reading path. **Joint actions are now plain labels** — the per-joint-action tier badge is removed from the exercise ribbon (`JointActionRatings`): tiering an individual joint action read as noise; the joint action just names the movement. FUTURE: exercise-quality tier is meant to become a community ranking (stability, resistance profile, progressive-overload-ability, …); for now Ollie sets tiers manually via `muscleTargets`.
- **2026-07-13** — **No bare text-only buttons; mobile-first is a hard rule** (AGENTS.md). Every actionable control keeps a visible resting background — `ghost` variant gained a `bg-translucent` fill so hover is no longer the only affordance. In-session logging fixes: removed swipe-to-delete (its red `bg-neg` reveal showed behind the set-options control and the trash target did nothing on desktop/tap) — delete lives in the `⋯` menu; removed the `overflow-hidden` on the exercise block so that menu isn't clipped; the `+RIR`/note panel now renders **above** the "Add set" button (was hidden beneath it); inputs use `bg-surface-2` + `border-border-strong` so they read as tappable.
- **2026-07-13** — **Session page two-tier header**: sticky `h-12` top bar (title / live duration / rest timer / End) — full-bleed hairline across the scroll pane, content in the `max-w-2xl` column; second non-sticky row below (conditions chip left, live "N sets · volume" stats right) scrolls away with content. Duration is quiet text; ~~minute-resolution (30s tick)~~ SUPERSEDED → now shows seconds (`formatDurationSeconds`, 1s tick, e.g. `1h 23m 45s`) per user request. Add exercise promoted ghost → outline (default variant).

## Architecture

- **2026-07-12** — Bun monorepo: `apps/web` (Vite React SPA) + `packages/core` (framework-free domain, Drizzle schema, `Repo` seam) + `packages/mcp` + `supabase/`. One language: TypeScript. No Rust.
- **2026-07-12** — All data access via `Repo` interface; `SupabaseRepo` is v1. `packages/core` stays free of React/DOM/supabase imports outside `repo/`.
- **2026-07-12** — jsonb-over-normalized precedent for light structured data (`tags`, `condition_values`, `metric_values`, machine `settings`, `muscle_targets`, `joint_actions`) — app-validated, no DB constraints.
- **2026-07-12** — Seed rows (`owner_id NULL`) are readable by all, writable only by migrations (RLS). Seed classifications fixed via future migration if wrong. Consequence: machine attach + classification editing are custom-exercise-only in UI.
- **2026-07-12** — Optimistic UI pattern: synchronous `onMutate` cache updates in `apps/web/src/lib/queries.ts`; logging path never waits on network. Initial JS ≤220 kB gzipped, CI-gated; heavy reference data (machine catalog) ships as lazy chunks.
- **2026-07-12** — Local prefs (unit, theme, lesson seen-state) live in localStorage via `useSyncExternalStore` modules in `apps/web/src/lib/` — no server prefs table.
- **2026-07-14** — **Committed sets open a full "Set details" modal.** ~~Editing a committed set used an inline weight/reps row plus an RIR/RPE/note panel underneath, and a ⋮ dropdown with Add-RIR/RPE/note/Delete items~~ SUPERSEDED. Tapping a committed set's weight/reps or its ⋮ now opens a single Radix `Dialog` ("Set N details") over everything, holding weight, reps, RIR (+lesson InfoTip), RPE, and a free-form multi-line **Note** (for machine/pad/seat settings, felt-notes, etc.), with a read-only **Rest** time (from `restSec`) and a live `e1RM ≈` readout, plus Delete (left) / Save (right). Rationale: editing a logged set is a correction, not the hot path — a modal reads clearer than stacked inline panels and finally surfaces rest time. The **active/draft** logging row is unchanged (keeps its inline ⋮ "add field" extras — fast keyboard-first entry; rest time doesn't exist until commit). Test IDs preserved (`committed-N-weight/reps`, `set-menu-N`, `edit-N-weight/reps/rir/rpe/save`, `set-menu-N-delete`).
- **2026-07-14** — **Training tab jumps into the live session.** When an active session exists, the Training nav item (sidebar + mobile island tab bar) points at `/session/:id` instead of `/train`, so tapping Training resumes the session directly rather than landing on the "Resume session" button. The tab stays highlighted for both `/train` and any `/session/*`. `/train` (start / start-new / resume affordances) is unchanged and still reachable directly. Resolved in `app-shell.tsx` via `useActiveSession` + `useLocation`.
- **2026-07-14** — **Headings set in mono.** All `h1/h2/h3` now use `--font-mono` (system `ui-monospace`/SF Mono stack — no new woff2, zero asset-budget cost), leaning into the "lab notebook / terminal" identity. Body stays Inter Variable. This is a **deliberate deviation** from the pure Linear-derived spec (Linear is all-Inter) — headings were the one place to add character without touching the dense keyboard-first logging path. Uppercase micro-labels (`text-2xs tracking-widest uppercase`) keep their own tracking utility and just render mono. Centralized in the base `h1,h2,h3` selector in `theme.css`; heading letter-spacing eased from -0.013em → -0.01em (mono runs wider, less negative tracking needed).
