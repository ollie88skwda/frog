# DECISIONS.md — SBL decision log

Terse, dated log of product/design/architecture decisions. **Rule: when a new decision overrides an old one, edit the old entry in place — mark it `SUPERSEDED → [see entry]` — so this file never contradicts itself.** Add an entry in the same commit as the change it describes.

## Product

- **2026-06-20** — SBL is a training lab notebook: log work + conditions, surface correlations ("Findings") with transparent stats, no AI/ML black boxes. Second moat: open data (export, PAT API, MCP). PRD: `docs/superpowers/specs/2026-06-20-sbl-prd.html`.
- **2026-06-20** — "SBL" is a placeholder name; single source `APP_NAME` in `packages/core/src/config.ts`.
- **2026-07-14** — **Navigation is Heavy-style: 3 tabs — Home / Training / Profile** (was 5: ~~Train / Library / History / Findings / Settings~~ SUPERSEDED). **Home** (`/`, index) is the lightweight dashboard: quick-start CTA, Findings teaser, Library entry, and a labeled placeholder for the future feed + graphs. **Training** (`/train`) is the full workout hub (start / resume the live session; routines later). **Profile** (`/profile`) holds the public-profile preview stub, recent History (+ link to full `/history`), and Settings (link to `/settings`). `/library`, `/history`, `/findings`, `/settings` remain routes, now reached from Home/Profile rather than top-level tabs. Start-session flow extracted to `useStartSession` (`apps/web/src/lib/start-session.ts`), shared by Home + Training. **Social feed + progress graphs are deferred** — placeholders only, not faked.
- **2026-07-12** — v1 web is online-first (Supabase-direct, account required). Offline deferred to mobile phase behind the `Repo` seam. Never promise offline in UI copy.
- **2026-07-12** — Exercise library organized by **muscle group (primary)** with joint action shown as a label per exercise. ~~Joint-action-primary~~ SUPERSEDED same day: joint actions shift target muscle by ROM (elbow flexion 20–90° biases biceps, >90° biases brachialis/brachioradialis) and grip (pronated/neutral biases brachialis) — too nuanced for top-level grouping.
- **2026-07-12** — **Tier ratings (S/A/B/C)**: per-exercise `muscleTargets` `{muscle, tier}` drives grouping/sorting; core `ACTION_RATINGS` (muscle × joint action → tier + nuance note + citations) powers education and "best exercise for a muscle". Tiers are evidence-informed judgment calls compiled from EMG/MRI/hypertrophy literature; thin evidence is flagged in notes.
- **2026-07-12** — **Machines are separate entities** (own library), not exercise fields: name, brand, catalog link, ordered numbered settings (`[{label, value}]`), notes, photo. In-session setup strip under the exercise header; edits persist to the machine row → "same setup every time, remembered forever".
- **2026-07-12** — **Machine catalog** is a static, lazy-loaded TS module (`packages/core/src/data/machine-catalog.ts`) of real commercial models (Matrix, Hammer Strength, Life Fitness, Technogym, …), scoped to major brands' strength lines — not a DB table, not "every machine ever". Catalog imagery = category line-art icons.
- **2026-07-12** — **Machine photos are user-taken only** (camera upload → private Supabase Storage bucket, owner-scoped). Third-party/manufacturer photos are copyrighted — "publicly visible" ≠ public property — and stay out.
- **2026-07-12** — **Lessons**: in-app micro-education (InfoTip → Dialog). Ultra-concise (couple of lines), optional tiny visual, optional `citations` (PMID/DOI). Seen-state in localStorage. First lesson: RIR (placeholder copy until Ollie supplies final).
- **2026-07-12** — **FUTURE (not built): PubMed science coaching** — rule-based (not necessarily AI) nudges citing studies when a plan choice contradicts evidence. Seams shipped now: `citations` on lessons and on `ACTION_RATINGS`.
- **2026-07-13** — **Exercise reference diagrams** (seed exercises only): `exercises.image_url` + `image_attribution`, hotlinked from Wikimedia Commons, no storage/upload. All diagrams are from the **Everkinetic set (CC BY-SA 3.0)** specifically so every diagram shares one consistent line-art style (same figure, same line weight) — deliberately not a mix of styles/sources. 19 of 20 seed exercises matched; **Face Pull** has no Everkinetic diagram and ships without an image. Custom (user-created) exercises get no image in v1 — out of scope, matches the existing seed-vs-custom asymmetry. Shown as a small `ExerciseThumb` (`apps/web/src/components/anatomy-ui.tsx`) in the library list, session exercise picker, and in-session exercise header. Store the Wikimedia **thumbnail** URL (~250px, `/thumb/.../250px-*.png`), never the full-res original (some originals are 250–400KB — wasteful for a UI thumbnail); for SVG-sourced diagrams, store the **rendered PNG thumb URL**, not the raw `.svg` — Wikimedia serves raw SVGs as `text/plain`, which silently fails to render via `<img src>`.
- **2026-07-13** — **Library exercise ribbon redesign**: bigger card per exercise (64px diagram, up from 24px) with explicit visual hierarchy — name (semibold) > per-joint-action tier ratings (color-coded S/A/B/C badges, computed) > machine/last-set metadata (faint, smallest). **Per-exercise joint-action tiers**: new `ratingsForExercise()` (`packages/core/src/domain/anatomy.ts`) looks up each of the exercise's own joint actions against `ACTION_RATINGS` restricted to the exercise's own target muscles (e.g. Front Squat × knee-extension → S via quads, × hip-extension → S via glutes) — reuses the existing evidence table, no new data. **Favorites**: `exercise_favorites` table (owner_id, exercise_id, favorite bool; upsert pattern mirroring `tracked_conditions`) since favoriting must work on shared seed rows — can't be a column on the shared `exercises` row. Plain star icon toggle, not a 3-dot menu: with only one action today, a dropdown-menu primitive isn't worth adding (no `@radix-ui/react-dropdown-menu` in the repo, bundle budget). **"Last set"**: reuses the existing `lastSetsForExercise` ghost-prefill lookup (no new query) via a new `useLastSets` hook. **"Machines used"**: shows the exercise's single currently-attached machine (`exercises.machine_id`) — there is no historical multi-machine log in the data model (session_exercises doesn't record machine), so this is the remembered current setup, not a history. Session logging screens (exercise picker, block header) keep the small 24px thumbnail — the ribbon redesign is Library-only, to protect the dense/fast keyboard-first logging path.
- **2026-07-15** — **Exercise/set-type logging UI (Hevy-parity M1 UI slice).** The session grid is now driven by the exercise's `exercise_type` (8 types, `@sbl/core` `TYPE_FIELDS`/`EXERCISE_TYPE_LABELS`/`EQUIPMENT_LABELS`). **Set-type markers**: the set-number cell (`SetTypeCell`, shared by draft + committed rows) opens a small menu — Normal / Warm-up / Failure / Drop — and the number is replaced by a coloured `W`/`F`/`D` marker (drop=accent, warm-up=warn, failure=neg; normal stays the faint number). Persists via `setType` on commit and on committed-row edit; committed rows also get **Remove set** in the same menu. **Per-type columns**: `columnsFor(type,unit,distUnit)` renders weight/distance/time/reps left→right per `TYPE_FIELDS`; the weight header uses `weightLabel` (`+kg`/`−kg` for weighted-/assisted-bodyweight), duration parses `mm:ss` or bare seconds (`parseDuration`), distance stored canonically in metres (km/mi display via unit). RPE/RIR extras appear in the ⋯ add-field menu only when `supportsEffort(type)` (rep-based types). **Inline duration stopwatch**: duration-type rows carry a count-up timer control; at most one runs per session (exclusive), and stopping writes elapsed seconds into the row's duration field (manual `mm:ss` entry stays available when it isn't running). **Per-exercise weight-unit override**: the weight column header is a menu (kg / lbs / Default) → `exercise_prefs` via `repo.setExerciseWeightUnit` + the `["exercise-prefs"]` query (satellite-on-seed-rows pattern, works on shared seed exercises); the block's display unit falls back to the global unit. **Custom-exercise form** gains Exercise Type + Equipment selects; type is locked once the exercise has logged sets (immutable — duplicate-as-custom is the reset path). Test IDs: `set-N-type`/`committed-N-type` (+`-{warmup,failure,drop,remove}`), `set-N-duration`/`set-N-timer`, `block-{name}-unit` (+`-{kg,lb,default}`), `exercise-type-select`/`exercise-equipment-select`. Draft-row hot-path invariants (ghost prefill, ~~blur-to-commit~~ **SUPERSEDED → 2026-07-17: blur no longer commits**, `a`/`e` hotkeys, optimistic logging) unchanged.
- **2026-07-15** — **Measures & progress photos (Hevy-parity M7 UI slice).** `/measures` (`apps/web/src/screens/measures.tsx`, hooks in `lib/measure-queries.ts`): entry editor is a native `<input type=date>` (backdate, `max`=today) over a 16-field grid — body weight, body fat %, and the 14 girths — each field blur-committing independently through **one upsert keyed by `measured_on`** (one entry/day; any subset; a field cleared to empty writes null). **Canonical vs display**: weight stored kg / shown per the global unit, girths stored+shown **cm-only in v1** (no in/cm toggle until the settings hub M12), body fat %, all at **0.1 precision** (measures use their own `round1`, not the 0.5-step `toDisplayWeight`). **Trend** is a hand-rolled inline-SVG line chart (no chart lib — bundle budget; theme-token stroke, `.num` date axis) with a horizontal metric-chip switcher and a newest-first dated list; tapping a list row loads that day back into the editor, delete is an inline confirm. **Progress photos**: `<input capture>` (camera on mobile, file elsewhere) → client resize to ≤1280px JPEG via canvas (mirrors `components/machines.tsx`, zero deps) → private `progress-photos` bucket; a top strip of thumbs opens a viewer with side-by-side **Compare** (any other day), **Replace**, and **Delete**. **Photo-delete branches on whether the day carries data** (`hasMeasurements`): an entry with measurements → `clearProgressPhoto` (nulls `photo_path`, removes the object, keeps the row); a **photo-only** entry → `deleteMeasurement` (drops the whole row) — matches Hevy ("deleting a photo deletes the entry only if it held nothing else"). Attaching a photo to an empty day first creates the row via the **awaited** `upsertMeasurement` so the upload targets the real server id (the optimistic client id never matches the inserted row). `/measures` reached from the ⌘K palette. e2e: `e2e/measures.spec.ts`.
- **2026-07-27** — **Voice set logging fills, never commits.** A mic button in the session header (`voice-log-mic`) takes one spoken utterance ("rear delt flies 250 lbs for 5 reps") and fills the matching block's **active row** — commit stays an explicit user action (Enter / Add set), because a mishearing that auto-logged a set would be worse than one the user can see and correct before committing. Pipeline: `parseSetUtterance` (`packages/core/src/domain/voice-parse.ts` — plain regex, no NLP dep; the connector for/x/by and the unit word are both optional) → `matchExerciseName`/`isConfidentMatch` (`domain/match-exercise.ts`) against **this session's own blocks only**, never the full library → an imperative `ActiveRowHandle.applyVoice` on the target row. **Unit precedence**: spoken unit word > the block's per-exercise `exercise_prefs` override > the session unit (one shared `blockUnitFor`, so the grid and the voice round-trip can't disagree); storage stays kg. **Ambiguity asks instead of guessing**: no confident match, or two blocks tied (same exercise logged twice), opens `VoiceMatchPicker` scoped to those blocks, duplicate names discriminated by session order ("Bench Press (2nd)"). Mic failures are routed, not flattened: `not-allowed` reads as blocked-permission, `network`/`audio-capture`/`service-not-allowed` as a recognition outage (Chrome's implementation is server-backed) — only genuine misses say "didn't catch that". The button is feature-detected on `isSecureContext` + `SpeechRecognition`/`webkitSpeechRecognition` (Firefox has none, iOS Safari is inconsistent) rather than rendered dead. e2e: `e2e/voice-log.spec.ts` — the recognition constructor is stubbed at page init (real audio can't be driven from Playwright); everything downstream of the transcript is the real code path.

- **2026-07-17** — **Active-row logging: kill blur-to-commit, add a checkmark control, move RIR/RPE/note/metrics into a details sheet, move the plate calculator into the ⋯ menu.** `ActiveRow`'s `onBlur` used to auto-commit a set whenever every active field was filled and focus left the row — simply tapping/tabbing away after typing weight+reps silently created a phantom set with no "Add set"/Enter/checkmark ever pressed. ## Architecture

- **2026-07-15** — **Settings hub, PWA, sounds, notifications + thin web-push, Strong import (Hevy-parity M12).** `apps/web/src/screens/settings.tsx` becomes a grouped hub (Units ×3, Workouts, Display, Notifications, Install, Export, Import, API tokens, Account). **Unit split**: weight (existing) + new **distance** (km/mi) + **body-measurement** (cm/in) prefs are device-local (`lib/settings.ts`, one shared `useSyncExternalStore` listener set); distance/measurement default to the weight system until overridden. **Server prefs** (`user_prefs` via `useUpdateUserPrefs`): default rest timer, previous-values scope, count-warm-ups-in-stats (also invalidates `["records-data"]`/`["stats"]`; the flag is already in the records query key so it recomputes), first weekday, body diagram (neutral-only v1). **Device prefs** (`lib/workout-prefs.ts`): smart-superset-scroll + rest-sound volume (existing, now surfaced with a WebAudio **Test** blip) + new `keepAwake` + `livePrBanner` toggles. **Warm-up method editor** (`lib/warmup-method.ts`): per-step %/reps rows (add/remove/reset), stored in localStorage; `getWarmupMethod()` returns a **cached, stable reference** (it backs a `useSyncExternalStore` snapshot — a fresh array per call thrashes React into a loop). **PWA**: `public/manifest.webmanifest` (+PNG icons 192/512/maskable + apple-touch, generated by `scripts/gen-pwa-icons.ts` via headless Chromium — no runtime dep, rebuild on rebrand), `public/sw.js` (app-shell cache-first for hashed `/assets`, network-first navigations, push + notificationclick handlers — **no offline-data promises**), registered from `main.tsx` behind `import.meta.env.PROD && !VITE_E2E` (E2E previews never race a caching layer). `alertRestDone` now routes through `registration.showNotification` when a SW exists. **Notifications/push** (`lib/pwa.ts`): permission request/status + a local test; thin web-push via `supabase/functions/send-rest-push` (PAT auth like `functions/api`, `npm:web-push`, prunes 404/410 subs). **VAPID is unconfigured** — the toggle shows "Requires server keys" and degrades to the guaranteed path (in-page audio + SW-local notification, plan §F); to activate, set `VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY`/`VAPID_SUBJECT` as function secrets + `VITE_VAPID_PUBLIC_KEY` in the web env. **Strong CSV import** shares one generic `WorkoutCsvImport` with Hevy (parse-preview → import, idempotent by started_at); **measurements CSV** added to Export. **Bundle**: settings/pwa additions stay off the eager chunk (settings is lazy; only `registerServiceWorker` is pulled into `index`, tree-shaking drops the hooks) — 224.1 kB gz. **Consumers still owned by m9-share's `session.tsx`** (reported, one-liners each): keep-awake (Wake Lock acquire/release), live-PR-banner gate, warm-up-method read (`warmupSets(w, getWarmupMethod(), …)`), previous-values-scope → `lastSetsForExercise(…, routineId)`. Also `.gitignore` now ignores `dist-*/` so agents' private e2e builds don't pollute lint. e2e: `e2e/settings.spec.ts`, `e2e/strong-import.spec.ts`.
- **2026-07-15** — **Library perf with the ~890-row seed: viewport-gate the per-row query, don't virtualize.** The library renders a `LastSetSummary` per exercise; `useLastSets` was ungated, so opening `/library` fired ~890 `set_logs` reads at once (measured 892), saturating the browser connection pool and starving concurrent background writes — this is what surfaced the two M4 e2e regressions (machine setting-save and custom-exercise insert both getting delayed/aborted). Fix: gate the last-set lookup behind a latching, single-shared-`IntersectionObserver` `useInView` hook (`apps/web/src/lib/use-in-view.ts`) so only on/near-screen rows query (892 → 11), plus `content-visibility:auto` + `contain-intrinsic-size` on rows for cheap off-screen paint. Chose this over list virtualization (AGENTS.md: "virtualize only when profiling demands") — initial render (~840 ms, React mounting 890 rows) is a one-time cost off the logging hot path, and search stays instant (~45 ms); virtualizing a grouped/collapsible/variable-height list would add complexity and break Playwright row visibility for little gain.
