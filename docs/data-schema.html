SBL — Data Schema

SQLite database via Drizzle ORM · Source: src/db/schema.ts · Last updated: 2026-06-21

Every table inherits five base columns (not repeated in each table below): id TEXT PRIMARY KEY (UUID v4), created_at INTEGER (Unix ms), updated_at INTEGER (Unix ms), deleted_at INTEGER nullable (soft-delete: NULL = active), dirty INTEGER 0|1 (sync flag: 1 = needs push to cloud).

exercises

The user's exercise library. Built-in exercises (future) have is_custom = 0; all user-created ones default to 1.

ColumnTypeNotes
nameTEXT NOT NULLDisplay name, e.g. "Incline Press (Machine)"
tagsTEXT JSONOptional string[] for light categorisation (e.g. ["chest","push"])
is_customINTEGER0 = built-in, 1 = user-created (default 1)
owner_idTEXTSupabase user UUID (null until cloud sync)

metrics

User-defined tracking variables. Session-scoped metrics become condition fields (sleep, stress, etc.); set-scoped metrics extend each set row (RPE override, form note, etc.).

ColumnTypeNotes
nameTEXT NOT NULLDisplay label, e.g. "Sleep (h)" or "Stress (1-10)"
typeTEXT NOT NULL'number' | 'scale' (1–10 integer) | 'text' | 'checkbox'
scopeTEXT NOT NULL'session' = logged once per session (conditions); 'set' = per set row
owner_idTEXTSupabase user UUID (null until cloud sync)

sessions

A single training session (workout). Starts when the user taps "Start session"; ends when they finish. Conditions (sleep, stress, etc.) are stored as a JSON blob keyed by metric ID.

ColumnTypeNotes
titleTEXTOptional freeform name, e.g. "Push A" or "FBEOD Day 1"
started_atINTEGER NOT NULLUnix ms — when the user tapped "Start"
ended_atINTEGERUnix ms — null while session is in progress
condition_valuesTEXT JSONRecord<metricId, number|string|boolean> — typed by each metric's type field

session_exercises

Junction between a session and an exercise. One row per exercise performed in a session; order_index preserves the sequence the user added them.

ColumnTypeNotes
session_idTEXT NOT NULL → sessions
exercise_idTEXT NOT NULL → exercises
order_indexINTEGER NOT NULL0-based position in this session's exercise list

set_logs

One row per set. Weight is always stored in kilograms; the UI converts to the user's chosen unit on display. Metric values (per-set custom variables) are a JSON blob keyed by metric ID.

ColumnTypeNotes
session_exercise_idTEXT NOT NULL → session_exercises
set_noINTEGER NOT NULL0-based set index within this session_exercise
weight_kgREALCanonical storage unit. Convert lbs at entry/display time.
repsINTEGERNull for time-based or bodyweight sets
rirINTEGERReps in Reserve (0 = technical failure, null = not logged)
noteTEXTFreeform set note
metric_valuesTEXT JSONRecord<metricId, number|string|boolean> — per-set custom metrics
completedINTEGER NOT NULL0 = planned (not yet done), 1 = completed. Default 1 for now.

Sync strategy (future — Plan 4)

Every row carries dirty = 1 on write. A background sync job pushes dirty rows to Supabase Postgres and clears the flag on acknowledgment. Conflicts are resolved last-write-wins using updated_at. Deletes are soft: deleted_at is set rather than removing the row, so the cloud can propagate the delete to other devices.
