## Diagnoses

**Item 2: the rule hid it. It was not a regression.** Last night's pinned footer works. The ruler renders and stays on screen from set 2, bilateral and per side, at 390x844, 390x397, 390x404 and 360x640, and on the sim with the keyboard up (`2-set2-perside-*`, and the session-ux2 tests that still pass). The cause is the 2026-11-25 rule "the ruler appears once the exercise has a logged set *in this session*". The first set of every exercise in every workout is the one where the boss lands, and it comes already filled with last time's numbers (`sim/2-sim-set1-keyboard-before.png`), but it had no ruler. So the ruler only showed after logging a set of that exercise today, which reads as "gone". **Fix:** the ruler shows when the value being edited has something to tune: a typed value, last time's ghost or prefill, the previous set's ghost, or a planned RIR. It still shows whenever the exercise has a logged set. A bare first set of a never-done exercise (nothing typed, no history) stays keyboard-only, as the original rule intended. The visual design is unchanged. Regression test: `e2e/session-ux3.spec.ts` "note 2". It failed on d02ebce (`regression-before.txt`: weight-ruler not found).

**Item 1.** Changing exercise swapped the whole `ExerciseSpotlight` in one frame, with no motion. The column now keys an `m.div` on the exercise. It slides in 56 px from the direction of travel and settles from 40% opacity, over `DUR_BASE` on `EASE_OUT` (lib/motion.tsx). There is no exit animation, so there is never a blank frame or two exercises on screen at once, and taps are never delayed. Direction comes from the index change, so prev/next buttons, swipe, the exercise picker and the auto-advance after a last set all slide the right way. Opening the session never slides. Reduced motion keeps only the fade (`MotionConfig reducedMotion="user"`). The sim showed one more jump: the entry panel waits on that exercise's last-time query, so the first visit showed a "no last data" panel for a frame or more, then the real numbers. Last time's sets for the exercises on either side are now prefetched, so the slide lands on a filled panel. Focus is unaffected: no `pointerdown` handlers were added, and the iOS focus fix (session-ux2 "touch press" test) still passes. Regression test: session-ux3 "note 1" (failed on d02ebce).

**Items 3 and 4.** Icons removed; chips are text-only, 44px. The position card is one `inputMode="decimal"` field with − / + `IconButton`s. Its value is read from the note ("Seat 4" → 4), so the field always shows what will be saved. Typing writes into the note live through the existing `applySetupSetting`. Emptying the field to retype leaves the note alone. Switching the setting (Seat → Pad) shows that setting's own value. Regression test: session-ux3 "notes 3 + 4" (failed on d02ebce).
